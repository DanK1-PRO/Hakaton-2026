# Неформальные ответы заказчика по ДДС

Дата фиксации: 2026-09-27. Источник: сообщение Даниила после неформального диалога с заказчиком. Статус: рабочие уточнения заказчика, часть пунктов всё ещё требует официального подтверждения.

## Что уточнено

- Версия классификатора, назначение получателей и источник правильных данных пока не определены заказчиком.
- Обязательный цикл реагирования ДДС: `Принято`, `Не принято`, `Начало реагирования`, `Прибытие`, `Проведение работ`, `Завершение`, `Отказ`.
- Нормативы времени:
  - 30 секунд с момента появления карточки/строки сообщения до открытия/подтверждения получения;
  - 3 минуты на открытие карточки и добавление первой записи: статус + текст;
  - остальные временные показатели по статусам не определены, работы могут идти часы или дни.
- Карточка считается отработанной, если все нужные статусы активированы и поля/комментарии заполнены. При отклонении нужен мотивированный отказ.
- Преподаватель является конечным валидатором. Его правки должны использоваться для будущего дообучения модели.
- Диспетчер ДДС не контролирует правильность заполнения карты от заявителя. Это зона оператора 112 и службы контроля 112.
- Диспетчер ДДС выбирает статусы в нижних полях карточки и добавляет комментарии к статусам. Редактирует только те поля, которые заполняет сам.
- При необходимости диспетчер ДДС может напрямую связаться с заявителем по обычному телефону, потому что номер уже есть в карточке. Это не основной маршрут MVP.
- Голосовое общение MVP ограничивается телефоном/IP-телефоном. Физический IP-телефон не обязателен; программная эмуляция достаточна.
- Основной голосовой маршрут ДДС: связь с вышестоящим начальником и руководителем/старшим группы реагирования. Старший группы сообщает обстановку и ход работ; либо диспетчер сам периодически звонит старшему.
- Службы для оператора 112 подтягиваются по опросной карте автоматически с возможностью ручного добавления. Для ДДС необходимые бригады выбираются вручную.
- Службы подтягиваются по району обслуживания и подчинённости. Пример: пожар в школе района Щукино с пострадавшими должен затронуть центральные службы 01/02/03, ДДС департамента образования, ДДС управы Щукино и ДДС СЗАО.
- Коды сценария реагирования — технические номера разработчиков 112. Для диспетчеров ДДС сценария реагирования нет; под сценарием 112 подтягиваются определённые ДДС.
- Специфики алгоритмов реагирования по службам заказчик не раскрывает; для MVP можно использовать универсальный алгоритм для всех.

## Как учитывать в проекте

- Для UI ДДС приоритет — статусы, комментарии, история, таймеры и телефонный тренажёр, а не редактирование исходной карточки 112.
- Справочник служб в UI является справочным/учебным: он показывает район/подчинённость/возможных получателей, но не выполняет автоматическое оповещение.
- Проверка ML пока не меняется: `ML_MODE=mock` остаётся регрессионным путём до готовности веток Кирилла/Максима.
