# Общий стартовый промт для AI-агентов участников

Версия: 2026-09-20. Репозиторий: https://github.com/DanK1-PRO/Hakaton-2026.git, private.

Этот файл можно дать Никите, Сане, Кириллу или Максиму. Участник копирует общий промт, добавляет блок своей роли и отправляет своей нейронке вместе с доступом к GitHub-репозиторию.

## Как использовать

1. Скопировать блок `Общий промт`.
2. Ниже добавить один блок из раздела `Ролевые вставки`.
3. Отправить нейронке участника.
4. Сначала получить от нейронки план и список файлов, которые она собирается менять.
5. Только после подтверждения разрешать реализацию.

## Общий промт

```text
Ты работаешь с приватным GitHub-репозиторием проекта:

https://github.com/DanK1-PRO/Hakaton-2026.git

Это хакатонный проект: тренажёр диспетчера ДДС / 112. В репозитории уже есть рабочая версия v0.1.0: FastAPI backend, React 18 TypeScript frontend, PostgreSQL 15, Docker Compose, mock/local ML gateway, тесты и документация.

Твоя задача — НЕ пересобирать проект с нуля и НЕ менять архитектуру без необходимости. Сначала изучи репозиторий и документацию, затем предложи короткий план работ в рамках моей роли.

Обязательно сначала прочитай:

1. AGENTS.md
2. README.md
3. README.en.md
4. docs/INDEX.md
5. docs/PROJECT_MAP.md
6. docs/ai/PROJECT_STATE.md
7. docs/VERIFICATION.md
8. docs/CURRENT_STATUS.md

Если моя роль относится к UI, дополнительно прочитай:

1. docs/team/DANIL_NIKITA_SANYA_UI_MASTER_SPEC.ru.md
2. docs/ui/SCREEN_MAP.md
3. docs/ui/UI_COMPONENT_INVENTORY.md
4. docs/ui/UI_BEHAVIOR.md
5. docs/ui/UI_SOURCE_MAP.md

Если моя роль относится к ML, дополнительно прочитай:

1. docs/team/KIRILL_MAXIM_ML_INTEGRATION_MASTER_SPEC.ru.md
2. docs/team/KIRILL_MAXIM_ML_INTEGRATION_MASTER_SPEC.en.md
3. docs/ML_INTEGRATION.md
4. config/evaluation_request.schema.json
5. config/evaluation_result.schema.json
6. ml/example_service.py
7. scripts/verify_local_ml.py

Главные правила:

- Не пушь напрямую в main.
- Создай отдельную ветку под мою задачу.
- Не меняй оригинальные данные заказчика в Данные заказчика/*.
- Не меняй красные зоны из мастер-ТЗ без отдельного согласования.
- Не ломай ML_MODE=mock.
- React не должен обращаться к ML напрямую.
- ML не должен писать напрямую в PostgreSQL и менять состояние сессии.
- Все пользовательские тексты интерфейса должны быть на русском.
- Если нужно изменить API/схемы/контракты, сначала остановись и задай вопрос.
- После изменений запусти релевантные проверки и напиши, что именно проверено.

Сначала ответь мне так:

1. Что ты понял о проекте.
2. Какая моя зона ответственности.
3. Какие файлы ты планируешь менять.
4. Какие файлы ты не будешь трогать.
5. Какую ветку предлагаешь создать.
6. Какие проверки запустишь перед PR.

После моего подтверждения переходи к реализации.
```

## Контроль перед началом работы

Если AI-агент сразу предлагает переписать архитектуру, заменить стек, вызвать ML напрямую из React, удалить существующие тесты или менять оригинальные данные заказчика, работу нужно остановить и вернуть его к мастер-ТЗ.

Перед реализацией он обязан явно назвать ветку, файлы, проверки и возможные риски конфликта с другими участниками.
