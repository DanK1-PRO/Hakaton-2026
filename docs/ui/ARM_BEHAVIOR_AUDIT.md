# Поведение АРМ ДДС: компактный аудит

Актуально на 20.09.2026. Статическое сопоставление с `backend/app/domain.py`, `frontend/src/workspace.tsx`, `frontend/src/arm/ServiceDock.tsx` и связанными API/моделями. «Поддержано» означает наличие в коде, не полную приёмку реального АРМ.

## Источники

**M**: `Данные заказчика/Датасет.zip::Работа с АРМ-112 для ДДС от ОКр_ГСИ.pdf`; текст `data_derived/raw/Работа с АРМ-112 для ДДС от ОКр_ГСИ.txt`. Локатор: страница по `PAGE N` и абсолютные строки TXT. Область: с. 11-26, 32-40.
**I**: `Данные заказчика/Инструкция_по_заведению_карточки_2507ГСИ.docx`; текст `data_derived/raw/Инструкция_по_заведению_карточки_2507ГСИ.txt`. Локатор: раздел и абсолютные строки TXT; страницы DOCX не предполагаются.
M приоритетнее I. I описывает оператора Службы 112: его функции нельзя автоматически считать полномочиями диспетчера ДДС. **UNKNOWN** означает, что правило не установлено проверенными источниками.

## Поддержано

- Автоматическая «Получена службой» при открытии своей поступившей карточки; открытие не заменяет подтверждение реагирования. M, с. 21, L505-L518. Реализация: API `open_card`, эффект открытия Workspace.
- Первые решения «Принята» / «Не принята»; после «Не принята» только «Принята»; после принятия доступны промежуточные этапы и конечные исходы. M, с. 25, L615-L623. Реализация: `TRANSITIONS`, `allowed_statuses`. Обязательного прохождения всех этапов источник не требует.
- Исправление ошибочной «Принята» через «Отказ от выполнения работ» с комментарием; ошибочной «Не принята» через «Принята». M, с. 32, L879-L888.
- Два отказных статуса требуют непустого комментария. Терминальные «Работы завершены» и «Отказ от выполнения работ» блокируют редактирование. M, с. 21-22, L532-L536, L566-L594; `react()`, `editable()`.
- ServiceDock показывает последний статус, время соответствующего события, раскрываемую историю статусов и комментариев одной службы. Телефон/редактирование не меняют время последней реакции. M, с. 25, L624-L628.
- Автообновление и защита от устаревшей версии присутствуют. Бегунок «Автообновление» не безусловно обязателен, если обновление включено по умолчанию. M, с. 11, L343-L345.

## Границы реализации

| Область | Требование источника и текущее ограничение |
|---|---|
| **Карточка ≠ служба ≠ занятие** | API `status` хранит `response_status` одной службы. M, с. 21, L517-L538 отдельно требует состояние карточки «Не оповещено», с. 22, L593-L594: «Отказ». Они отсутствуют; красный таймер их не заменяет. Завершение занятия также не равно завершению работ службы. |
| **Одна ДДС** | Текущий scope намеренно учебный: один статус и история одной ДДС. M, с. 14, L372-L375; с. 25, L624-L633 описывает блоки оповещённых служб. Независимые назначения, состояния, авторы и история других служб не реализованы. |
| Список оповещения | UI честно обозначает маршруты ЕКП справочником без фактической передачи. M, с. 14-15, L386-L414: признаки определяют итоговый тип и службы. Заполненная условная строка классификатора не доказывает оповещение; правила условий нельзя домысливать. |
| **30 секунд** | M, с. 21, L517-L531: от направления карточки конкретной службе до «Принята» либо «Не принята». Сейчас отсчёт от `created_at`; это учебное допущение при совпадении создания и направления, не универсальное правило. Просрочка не запрещает последующее решение. |
| **Передача при наличии** | M, с. 21, L532-L536; с. 22, L586-L592: причина отказа обязательна, сведения о передаче другим службам нужны **при наличии**. UI/API требуют непустой текст, но формулировки ошибки и справки теряют оговорку. Не требовать выдуманной передачи. |
| Завершение | M, с. 22, L571-L576: необходимые дополнительные сведения и результаты отражаются в комментарии до закрытия. Сейчас `completed` допускает пустой комментарий; содержательная полнота не проверяется. Официальный шаблон/минимальная длина не заданы. |
| Автор реакции | M, с. 25, L630-L633: ФИО/номер перед временем; номер раскрывает ФИО; для ВИС «оп. 9999». Исторический автор в ServiceDock не показан. Текущий пользователь в поле «Оператор» не заменяет автора сохранённого события. |
| 103/104 | M, с. 23, L599-L602: 103 вместо двух отказов использует «Работы завершены: Завершение работ без бригады»; 104 иногда не передаёт комментарии. Специализированных правил нет; исключение 104 нельзя распространять на обычную ДДС. |
| Происхождение/сведения | M, с. 14, L376-L383: ВИС может не передать опросную карту/признаки; пострадавшие бывают только в описании. M, с. 19, L471-L476 требует учитывать свободные описания. «Нет данных» в UI корректно обозначает отсутствие сведений, а не отрицательный факт или реализованное поле API. |
| Поиск | M, с. 35-40, L987-L1071: карточки своей службы; отдельные критерии типа/признаков, адреса, округа, района, описательного адреса, региона, службы, описания, канала, ВИС/оператора и **статуса карточки**. Общий q, тип и статус службы покрывают лишь часть; владение обучающегося не равно принадлежности службе. |
