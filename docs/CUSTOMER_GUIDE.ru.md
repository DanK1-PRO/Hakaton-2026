# Инструкция для заказчика

Обновлено: 29.09.2026. Документ отвечает на четыре вопроса: что доступно с репозиторием,
можно ли поднять сервер «прямо в GitHub», какими способами запустить и проверить систему
и где лежит каждая инструкция. Состав функций он не меняет.

## 1. Что вы получаете

Репозиторий: `https://github.com/DanK1-PRO/Hakaton-2026` (приватный).

| Возможность | Комментарий |
|---|---|
| Просмотр кода, истории коммитов, diff, веток | доступ по инвайту |
| Заведение Issues (шаблон бага) и Pull requests (шаблон) | при доступе collaborator |
| Вкладка Actions: статус проверок, артефакт отчёта браузерных тестов | читается по read-доступу |
| Release `modelURL` с весами локальной модели | отдельный пункт ниже |
| Скачивание архива `Code → Download ZIP` | без установки git |
| Автоматический запуск сервера/сайта на стороне GitHub | **не предусмотрено** (см. §3) |

Приватный репозиторий не открывается по ссылке без инвайта: Settings → Collaborators →
Add people. Read-доступа достаточно для просмотра, CI и скачивания архива; для Codespaces
(§6) нужны права на запись. Лицензия на публичное распространение не назначена, исходные
документы заказчика остаются за их правообладателями.

## 2. Порядок действий: с чего начать

1. Открыть `README.md` — быстрый старт, учётные записи, архитектура.
2. Выбрать подход запуска: A (Docker), B (Windows), C (Codespaces) — §4–§6.
3. Пройти демонстрацию за 3–5 минут: `docs/DEMO.md`.
4. Посмотреть раздел «Готовность» (`/readiness`) — паспорт стенда: локальность, режим ML,
   карта, данные, документы и проверки.
5. Сверить результаты автоматических проверок: `docs/VERIFICATION.md` и вкладку Actions.

## 3. Можно ли поднять сервер прямо в GitHub

Честный ответ: **напрямую — нет, и это осознанное решение текущей версии.**

- **GitHub Actions** (`Quality and integration`) — это непрерывная проверка кода
  (линтер, тесты, сборка, браузерные сценарии, smoke-сборка Docker), а не деплой.
  Деплой-воркфлоу, GitHub Pages и конфигурации облачного хостинга в репозитории отсутствуют.
- **Что можно в GitHub без своего сервера:** открыть окружение Codespaces (§6),
  скачать архив, запустить CI вручную кнопкой «Run workflow», скачать отчёт тестов.
- **Что требует отдельного согласования:** публичный стенд для жюри. Нужен внешний
  хостинг, TLS и отдельные пароли (`docs/DEPLOYMENT.md`, раздел «Учебная сеть»);
  сейчас он не настроен и не публиковался.

## 4. Подход A · Docker Compose (основной)

Требования: Docker Desktop/Engine с Compose v2, Python 3.11+ для подготовки конфигурации,
свободные порты 8080 и 8000. Работает в Linux/macOS/Windows.

```bash
git clone https://github.com/DanK1-PRO/Hakaton-2026.git
cd Hakaton-2026
python scripts/init_local.py
docker compose up --build -d --wait
```

- UI: `http://localhost:8080`
- API/Swagger: `http://localhost:8000/docs`
- Health: `http://localhost:8000/health`
- Логи/статус: `docker compose ps`, `docker compose logs api`
- Остановка: `docker compose down` (том с данными не удалять)

Подробности и резервирование: `docs/DEPLOYMENT.md`.

## 5. Подход B · Windows без Docker

Требования: Python 3.11/3.12, Node.js 22.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
npm.cmd ci --prefix frontend
npm.cmd ci --prefix scripts/windows
.\.venv\Scripts\python.exe scripts\init_local.py
powershell -ExecutionPolicy Bypass -File scripts\windows\start-app.ps1
```

UI: `http://127.0.0.1:5173`, API: `http://127.0.0.1:8000/docs`, PostgreSQL в `.runtime`
(порт 55432, служба не устанавливается). Остановка:
`powershell -ExecutionPolicy Bypass -File scripts\windows\stop-app.ps1`.
Если путь к репозиторию содержит кириллицу, скрипт поднимает псевдодиск `P:`; при занятом
`P:` используйте путь без кириллицы или Docker.

## 6. Подход C · GitHub Codespaces (облако GitHub)

Не требует установки Docker/Python/Node на вашей машине: окружение поднимается в облаке
GitHub из файла `.devcontainer/devcontainer.json`, который уже подготовлен в репозитории
(Python 3.11, Node 22, Docker-in-Docker, проброс портов 8000/8080/5173).

1. Нужен инвайт collaborator (права на запись) — read-only доступ Codespaces не даёт.
2. Открыть `https://codespaces.new/DanK1-PRO/Hakaton-2026` или кнопку
   **Code → Codespaces → Create codespace on main**.
3. Дождаться создания окружения, затем в терминале:

```bash
python scripts/init_local.py
docker compose up --build -d --wait
```

4. Во вкладке «PORTS» пробросить порт `8080` (Forward on browser) — откроется интерфейс;
   `8000` → Swagger.

Ограничения: это временное облаковое окружение, а не боевой сервер. Для аккаунта GitHub Free
действует лимит 120 core-hours в месяц (≈60 часов на стандартной 2-ядерной машине),
далее — оплата по тарифу GitHub. Тестовые данные Codespaces не предназначены для
постоянного хранения: учебные результаты сохраняйте в локальном запуске или экспортом
(`docs/DEPLOYMENT.md`, «Резервирование»). На приватном репозитории время Actions и
Codespaces списывается из лимита бесплатного тарифа.

## 7. Как проверять код: CI и тесты

Автоматический прогон запускается на каждый push и pull request. Ручной запуск:
вкладка **Actions → Quality and integration → Run workflow** (кнопка справа), ветка `main`.

| Проверка | Что делает |
|---|---|
| `ruff check backend ml scripts` | линтер Python |
| `pytest -q` | серверные тесты (42) |
| миграции + seed + `verify_local_ml.py` | схема, демо-данные, контракт ML |
| `npm run build` | типизация и сборка интерфейса |
| Playwright (chromium, desktop + mobile) | браузерные сценарии (28), отчёт уходит в артефакт `playwright-report` |
| `docker compose up --build` + curl | работоспособность контейнерного запуска |

Локально те же проверки выполняются командами из раздела «Проверка» файла `README.md`.

## 8. Режимы ML: что включать

| Режим | Когда | Что доступно |
|---|---|---|
| `ML_MODE=mock` (по умолчанию) | без сети и без модели | вся учебная механика, детерминированная резервная проверка |
| `ML_MODE=local` | запущен evaluator + локальная модель | реальная оценка комментариев и **генерация учебных сценариев в интерфейсе преподавателя** |

Веса: Release `modelURL`. Порядок запуска: `docs/LOCAL_ML_RUN.ru.md`.
При недоступной модели система не падает: проверка переходит в резервный режим с явной
пометкой в интерфейсе.

## 9. Проверочный список после запуска

1. `GET /health` → `status=ok`, `database=ok`.
2. Раздел «Готовность» (`/readiness`) — паспорт стенда.
3. Войти как `trainee@dds.local` / `DdsDemo2026!` → «Учебные задания» → начать занятие →
   «Принята» → реагирование → «Работы завершены» → «Завершить занятие».
4. Войти как `instructor@dds.local` → «Контроль занятий» → заключение; при `ML_MODE=local`
   — кнопка «Генерация сценариев».
5. `http://localhost:8000/docs` — OpenAPI всех эндпоинтов.
6. Вкладка Actions — зелёный прогон `Quality and integration`.

Полный сценарий показа: `docs/DEMO.md`. Учётные записи и пароль по умолчанию меняются
через `DEMO_PASSWORD` до первого заполнения базы.

## 11. Границы версии (честные ограничения)

- Учебный локальный контур: реальные вызовы 112/ДДС не выполняются, это не сертифицированная
  боевая АРМ.
- Нет реального голоса (ASR/TTS), SIP, автоматического дообучения модели, точного
  геокодирования, группового обучения и расширенной аналитики.
- Официальная методика балльной оценки не утверждена: система показывает замечания и время;
  балл экспериментальный, заключение преподавателя отдельное.
- Данные синтетические; шифрование персональных полей и соответствие ГОСТ не заявляются.
- Детально: `docs/FINAL_INTEGRATION_AUDIT.ru.md`.

## 12. Частые вопросы

**Поднимется ли сервер автоматически после клонирования?** Нет. Есть три подхода
запуска (§4–§6); автоматического деплоя в облако не настроено.

**Нужен ли Docker?** Для подхода A — да. Для B и C не нужен.

**Можно ли тестировать разные подходы параллельно?** Да: A и B независимы (разные порты и
БД), C изолирован в облаке. Данные каждого подхода не смешиваются.

**Можно ли менять код и предлагать правки?** Да, через ветки и Pull request (шаблон уже в
репозитории). После стоп-кода 29.09.2026 23:59 МСК изменения не входят в сданную версию:
фиксируйте commit SHA отдельно (`docs/SUBMISSION.ru.md`).

**Как сообщить о проблеме?** Issues → шаблон бага (репозиторий, commit SHA, шаг воспроизведения, подход запуска).

**Где взять веса модели?** Release `modelURL`, инструкция `docs/LOCAL_ML_RUN.ru.md`.
