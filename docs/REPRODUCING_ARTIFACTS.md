# Воспроизведение Материалов

Обычный запуск использует готовые данные из Git. Оригиналы заказчика нужны только
для повторного извлечения. Они остаются локальными и не загружаются в репозиторий.

## Данные И Контракты

В отдельном Python-окружении установите `backend/requirements.txt` и
`scripts/requirements-tools.txt`.

1. `python scripts/inventory_sources.py`: идентичность файлов и содержимого ZIP.
2. `python scripts/extract_sources.py`: локальный, исключённый из Git кэш чтения.
3. `python scripts/build_classifier.py`: классификатор и синтетические примеры.
4. `PYTHONPATH=backend python scripts/export_contracts.py`: OpenAPI/JSON Schema.

В PowerShell перед пунктом 4: `$env:PYTHONPATH='backend'`.
Не заменяйте исходные файлы выгрузкой; проверьте diff и provenance перед коммитом.
Повторное заполнение БД не является миграцией обновлённых справочников:
для новой версии данных нужна отдельная миграция/команда импорта.

## Скриншоты И PDF

Запустите API/UI/PostgreSQL, затем `npm test --prefix frontend`.
Playwright обновляет фактические снимки в `docs/images/`.
Для PDF на Windows: `python scripts/build_manual.py`.
Используются установленные системные шрифты Arial; на другой ОС нужно явно
подобрать совместимый шрифт с кириллицей перед генерацией.
Готовый PDF находится в `docs/delivery/`, PNG для визуальной проверки
каждой страницы в исключённом из Git каталоге `.runtime/pdf-preview/`.

Проверьте все страницы, таблицы, переносы заголовков и снимок интерфейса.
Наличие сформированного PDF не означает утверждение документа заказчиком.
