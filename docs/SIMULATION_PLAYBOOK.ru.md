# Playbook симуляции ДДС: исходы, варианты, закрытие пробелов

Версия: 2026-09-22. Статус: рабочий продукт-документ для хакатона.  
Метки: `CITE` — источник; `TEAM_PROPOSAL` — выбор команды; `OPTIONS` — варианты на выбор заказчика/команды; `UNRESOLVED` — ждём заказчика; `ML_HOOK` — точка подключения модели.

Связанные файлы: `docs/OPEN_QUESTIONS.md`, `docs/OPEN_SOURCE_RESEARCH.ru.md`, `docs/ai/DECISIONS.md`, `docs/ML_INTEGRATION.md`, `config/evaluation_*.schema.json`.

## 0. Контур обучения (кого учим)

| Вопрос | Решение | Метка |
|---|---|---|
| Оператор 112 или ДДС? | **Оба контура в одном тренажёре**, роли: карточку заводит «Система-112» (вход), **основная практика — диспетчер профильной ДДС** | `OPTIONS` A1 |
| Почему так | ПП 1931: оператор 112 — общая часть; ДДС — специальная часть и реагирование | `CITE` №1931 пп.8–9 |
| Текущая сборка | v0.1.0 = **роль диспетчера ДДС** (памятка ОКр_ГСИ); вход 112 = источник карточки, не отдельный mode | `CONFIRMED_CUSTOMER` + `TEAM_PROPOSAL` |

**Варианты расширения (выбрать при доработке):**

1. **Только ДДС** (сейчас) — минимальный контур.  
2. **112 → ДДС** — отдельный экран опроса заявителя (75 с), затем передача в ДДС.  
3. **Ролевой переключатель** — trainee выбирает режим при входе в занятие.  
4. **Двойной зачёт** — одна сессия: сначала 112, потом ДДС, единый журнал.

Рекомендация хакатона: **(1) сейчас, (3) как следующий слой** — не ломает API.

## 1. Профиль «нашей» ДДС (зона ответственности)

Пробел C1 закрыт: в UI есть **справочник профилей** (`frontend/src/domain/ddsProfiles.ts`) и выбор профиля на экране заданий.

### Варианты профилей (`OPTIONS` — доступны все)

| id | Название | Зона по умолчанию | Своё реагирование | Типичный отказ |
|---|---|---|---|---|
| `district_utility` | ДДС учебного района (ЖКХ) | район / участок | аварийная бригада ХВС/ГВС/электро | чужой баланс, чужая линия связи |
| `fire` | Учебная ДДС охраны (МЧС-профиль) | объект / округ | пожарное реагирование | не пожарный характер, нет признаков горения |
| `police` | Учебная ДДС правопорядка | участок | вызовы 102-профиля | гражданско-правовой спор, нет признаков ПС |
| `ambulance` | Учебная ДДС скорой помощи | участок | выезд бригады 103 | консультация без выезда, профиль иной клиники |
| `gas` | Учебная ДДС газовой службы | газифицированный участок | газовая аварийная | нет запаха/показаний, объект не газифицирован |
| `mixed` | Смена ЕДДС (смешанная) | весь муниципалитет | по классификатору маршрутов | определяется по типу и классификатору |

Правила выбора зоны (`OPTIONS`):

- **Территория:** район → округ → город (ЕДДС).  
- **Объект:** жилой фонд / улица / дорога / инфраструктурный объект.  
- **Баланс:** свой объект → Принята; чужой → Не принята + передача.  
- **Профиль работ:** есть бригада и полномочия → реагирование; нет → передача/консультация.

Источник рамки: ПП 1931 (зона ответственности при перенаправлении), методрекомендации ВНИИ ГОЧС (знание зон территории — обязанность диспетчера), клиентская памятка (отказ по принадлежности). `CITE` + `TEAM_PROPOSAL` для состава профилей.

## 2. Полный граф исходов симуляции

```text
[Вход: карточка от 112 или ручное создание]
        │
        ▼
[Открытие карточки] ── авто «Получена службой» (≤30 с окно подтверждения)
        │
        ├── Просрочено 30 с → критическое замечание, решение всё равно возможно
        │
        ▼
[Первое решение ≤30 с с направления]
   ├── Принята ──────────────────────────────────► [Реагирование]
   │      ├── Начало реагирования
   │      ├── Прибытие
   │      ├── Проведение работ
   │      ├── Работы завершены ──► TERMINAL, lock
   │      ├── Отказ от выполнения работ + причина ──► TERMINAL, lock
   │      └── (опционально) уточнение → обратный звонок заявителю
   │
   ├── Не принята + причина (+ передача при наличии)
   │      └── Принята (исправление ошибочного отказа)
   │             └── далее как в Реагировании
   │
   └── [Ветка: консультация без выезда]  (газ/ЖКХ/скорая, «Консультация»)
          └── завершение без бригады — триггер «Консультация» (ПП 1931 прил.2)
                 TEAM_PROPOSAL для UI-флага; в MVP — фиксируется комментарием
```

### Дополнительные контуры (дочерние процессы)

| Контур | Исходы | Реализация |
|---|---|---|
| **Уточняющие вопросы** | уточнил адрес/этаж/людей → верные данные; не уточнил → замечание «missing_information» | чек-лист в help; ML_HOOK: список полей |
| **Обрыв связи** | ≥3 обратных вызова, ≤10 с на инициирование, ожидание ≤1 мин (№1931) | mock-телефон + подсказка; таймеры `OPTIONS` |
| **Перенаправление голоса 112→ДДС** | двойное подтверждение: получение + зона | вне MVP; документ для этапа mode=operator |
| **Консультация ≤2 мин** | без выезда → завершено | флаг/статус `OPTIONS` |
| **Психологическая поддержка ≤30 мин** | отдельная сессия | вне MVP |
| **Мультислужба** | снятие с контроля ЕДДС только после всех ДДС | будущий блок «Привлечённые ДДС» |
| **ЧС / режим повышенной готовности** | приоритет в ЕДДС | кнопки ЧС/ЧП сейчас disabled — `OPTIONS` |
| **Иностранный язык** | переводчик/оператор-владелец | вне MVP |
| **Ложный вызов** | №1931 не регулирует → `UNRESOLVED` | не реализуем без КоАП-права |
| **Терминальная ошибка** | «отдел контроля» по памятке; у нас — заключение преподавателя | уже есть |

### Полный список уточняющих вопросов заявителю (`OPTIONS`, чек-лист UI)

1. Точный адрес: улица, дом, корпус, строение.  
2. Этаж происшествия и этажность здания.  
3. Характер происшествия (что произошло).  
4. Угроза распространения (на жилой массив, соседние объекты).  
5. Наличие людей, угроза жизни, число пострадавших.  
6. Контактный телефон (если отличается от АОН).  
7. Доступ для бригады (ворота, шлагбаум, парковка).  
8. Признаки опасности: газ, открытый огонь, обрушение, провода под напряжением.  
9. Кому принадлежит объект / какая организация обслуживает (для отказа по принадлежности).  
10. Нужна ли консультация без выезда.

Источники вопросов 1–5: должностная инструкция диспетчера ЕДДС (pzpushkinskoe), Приложения 1–2 ПП 1931. 6–10: `TEAM_PROPOSAL` (практика ЖКХ/АДС).

## 3. Нормативы таймеров (закрыто `CITE`)

| Параметр | Норматив | В симуляторе |
|---|---|---|
| Ожидание ответа оператора 112 (98%) | 20 с | не в роли 112 |
| Среднее ожидание ответа | 8 с | — |
| Опрос до готовности карточки | 75 с (среднее) | будущий mode=operator |
| **Подтверждение приёма ДДС** | **30 с** | **есть** |
| Обратный вызов при обрыве | ≤10 с, ≥3 попытки, ожидание ≤1 мин | подсказка |
| Консультация | ≤2 мин | подсказка |
| Психподдержка | ≤30 мин | вне MVP |
| Хранение вызова | ≥3 года | вне MVP (ОВД) |

Точка отсчёта 30 с: официально — **момент отправки карточки ДДС**; в MVP = `created_at` (совпадает при синтетике) — `TEAM_PROPOSAL`, B8.

## 4. Оценка и ML (подготовка к неполной модели)

### Контракт (уже заморожен)

- `config/evaluation_request.schema.json` / `evaluation_result.schema.json`, `schema_version=1.0`.  
- `score` может быть `null` — **балльной методики нет** (`UNRESOLVED` A3).  
- `routing_assessment` = `not_scored` — условные маршруты **не** авто-оцениваем (B4).  
- `comment_quality` = `requires_instructor_review` — смысл комментариев = преподаватель.  
- Любой сбой ML → `mode=fallback` / `mock`, занятие не встаёт.

### Режимы на время хакатона (`OPTIONS`)

| Режим | Когда | Поведение UI |
|---|---|---|
| `mock` | по умолчанию, CI | «Учебная проверка» |
| `local` | модель отдаёт `/v1/evaluate` | «Локальная модель» |
| `fallback` | таймаут/битый ответ | «Резервная проверка» + баннер |
| `partial` | модель даёт часть блоков | **заполняется то, что есть; остальное → instructor** (`ML_HOOK`) |

### Что ждём от моделей (чтобы потом было просто дописать)

1. **Evaluator** — уже контракт; Maxim `ml/scoring-experiment`: перед мержем `score` либо `null`, либо пометить `TEAM_PROPOSAL`; `routing` → `not_scored`.  
2. **Генератор сценариев** — DTO отдельный; выгрузка в `data_derived/scenarios/` + `source.status`.  
3. **ASR/диалог** — поля транскрипта в actions (`kind=transcript`) — **не трогать UI, пока нет контракта**.  
4. **Сложность/классификация** — может подсказывать тип, но **не** переопределять `incident_type_id` без действия пользователя.

### Частичная модель: правило интеграции

```text
Если ML вернул только critical_errors → показать их + «поле/действия проверит преподаватель»
Если ML вернул score=null → не рисовать балл
Если ML недоступен → fallback, не блокировать «Завершить занятие»
Обратная связь преподавателя append-only, не перетирает машинный результат
```

## 6. Чек-лист «оператор готов к реальной АРМ»

- [ ] Отличает 112 / ДДС / ЕДДС и кто что заполняет.  
- [ ] Знает зону своей службы и 3 способа решения: принять, отказать, консультация.  
- [ ] В окне 30 с ставит Принята/Не принята.  
- [ ] При отказе пишет причину и передачу (если была).  
- [ ] Уточняет адрес, этаж, людей, угрозу распространения.  
- [ ] Помнит нормативы 20/8/75/30/10/3/1/2/30.  
- [ ] Знает маршрут-справочник ≠ фактическое оповещение.  
- [ ] Видит в результате: замечания, время, комментарий преподавателя.  
- [ ] Не ждёт балла, пока методика не утверждена.  
- [ ] При падении ML понимает «резервная проверка» ≠ отказ системы.
