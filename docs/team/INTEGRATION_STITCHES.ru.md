# Журнал стыков веток

Версия: 2026-09-21. Репозиторий: `DanK1-PRO/Hakaton-2026`.

Этот файл фиксирует все найденные стыки между ветками команды. Стык не означает, что ветка плохая. Это место, где при финальной сборке может возникнуть конфликт файлов, тестов, API, UI-поведения, данных или документации.

## Правило работы

- Если при ревью, merge-check или тестах найден стык между ветками, он добавляется в этот журнал.
- Ничего не чинить молча в чужой зоне без решения Даниила.
- Перед финальным прогоном на Astra вывести этот журнал целиком и решить по каждому пункту: исправляет владелец ветки, исправляет Даниил/Codex на интеграционной ветке, переносится на следующий проход или закрывается как неактуальный.
- После исправления пункт не удалять сразу: перевести в `resolved`, чтобы история решений осталась понятной.

## Статусы

| Статус | Значение |
|---|---|
| `open` | Стык найден, решение ещё не принято. |
| `owner-fix` | Лучше исправить владельцу ветки. |
| `integrator-fix` | Лучше исправить в общей интеграционной ветке. |
| `watch` | Сейчас не мешает, но проверить при финальном merge. |
| `resolved` | Исправлено и проверено. |

## Как добавлять новые пункты

1. Дать пункту новый ID вида `STITCH-003`.
2. Указать ветки, область, фактическую проблему и предлагаемое действие.
3. Не назначать виноватого: стык является задачей интеграции, а не оценкой участника.
4. После решения добавить короткую пометку, где и каким коммитом исправлено.
