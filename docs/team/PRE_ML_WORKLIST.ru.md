# Что делать до интеграции ML

Версия: 2026-09-21. Цель: подготовить UI/API-обвязку так, чтобы ML-модели Максима/Кирилла подключались без переделки рабочего места диспетчера.

## Приоритет 1 — интерфейс и источники

1. **Второй визуальный проход по всему интерфейсу.**
   Сверить не только ДДС-карточку, но и список происшествий, карточку 112, нижнюю панель служб, оранжевую панель действий, режим статуса и мобильный вид. Источники: `СКРИНШОТ ДДСГСИ.docx`, `СКРИНШОТ КАРТОЧКИ 112ГСИ.docx`, `Работа с АРМ-112 для ДДС от ОКр_ГСИ.pdf`.

2. **Развести ДДС и карточку 112.**
   Скрин с оранжевой нижней панелью относится к карточке 112/операторскому заполнению. Его можно использовать как визуальный источник для общих блоков: адрес, сценарные теги, службы, кнопки сохранения. Но нельзя автоматически переносить полномочия оператора 112 в ДДС без подтверждения источником.

3. **Учебные подсказки не в основной сетке.**
   Основной экран должен повторять АРМ. Дополнительные пояснения тренажёра лучше держать в `?`, drawer/help, tooltips и результатах занятия, чтобы обучающийся не ожидал эти элементы в реальном АРМ.

## Приоритет 2 — карта и адрес

1. **Карта через adapter, не напрямую в карточке.**
   Сделать `mapProvider`/`MapPanel` с режимами `disabled`, `mock`, `yandex`. По умолчанию `mock`, чтобы проект работал без внешнего ключа и интернета.

2. **Yandex Maps только при наличии ключа.**
   Для реальной карты нужен ключ API и согласование сетевого режима. Переменная: `VITE_YANDEX_MAPS_API_KEY`. Без неё кнопка `карта` открывает учебную заглушку с адресом и пояснением.

3. **Структурировать адрес.**
   Сейчас адрес хранится одной строкой. До ML можно добавить frontend-only разбор/панель: страна, субъект, населённый пункт, округ, район, улица, дом, корпус, подъезд. Сохранение в API оставить прежним, пока backend-схема не расширена.

## Приоритет 3 — подготовка к ML

1. **Контракт входа ML.**
   Зафиксировать, какие поля UI отдаёт модели: описание, адрес, тип происшествия, признаки, история статусов, комментарии, время подтверждения.

2. **Контракт выхода ML.**
   Зафиксировать, что ML может вернуть: подсказка статуса, замечания, оценка полноты комментария, классификация, рекомендации по маршрутам. UI должен показывать это как учебную подсказку, а не как официальное действие службы.

3. **Проверка degraded mode.**
   Если ML недоступна, карточка, статусы, результаты и mock-проверка продолжают работать.
